Learn Terraform with Phoebe

A data platform is buckets, catalogs, warehouses and grants, and most teams build it by clicking. Six sessions on writing it down instead: why declarative code beats click-ops, the HCL language, the state file that Terraform trusts more than your memory, modules and version pins, how to read a plan the way a reviewer should, and how to ship changes through a pull request. Everything runs on your laptop with the terraform or tofu CLI, at zero cost, with no cloud account. Every command and output on these pages was really run.

The six sessions 🧭 · from the first config to a reviewed apply

The running case is Larkspur Freight, a constructed mid-size logistics company building its first data platform as code: a lake with raw, curated and serving zones in dev and prod, a catalog, and the grants on top. It grows one piece per session. Larkspur Freight is invented for teaching, and every page says so.

🏗️ Session 1 · foundations

Why infrastructure as code

Click-ops against declarative code, desired state against actual state, providers and resources, and the init, plan, apply, destroy loop on a first config that runs on your laptop.

▶ Start here 📝 Session 2 · foundations

The HCL language

Blocks, types, variables with validation, outputs, locals and data sources, and why for_each keys survive a reordered list when count indexes do not. The lake zones, per environment.

for_each over count 🗄️ Session 3 · core

State is the source of truth

What the state file holds, including your secrets in plain text. Break it three ways, lost, drifted and renamed, then fix it with import and moved blocks, state commands, a backend and a lock.

break it, fix it 🧩 Session 4 · deeper

Modules and versions

One data-zone module used by dev and prod, version constraints and the lock file, and the same module shown against AWS, Google Cloud, Snowflake and Databricks resources.

one module, two envs 🔎 Session 5 · bench night

Read a plan like a reviewer

Plan symbols, force-new attributes, lifecycle guard rails and the dependency graph that sets the apply order, on a plan simulator you can edit. A plan can look small and still destroy data.

★ the bench 🚢 Session 6 · deeper

Plan on the PR, apply on merge

Directories against workspaces, a GitHub Actions gate, saved plans that go stale, HCP Terraform against OpenTofu, the licence split, and a map of the Associate (004) exam.
